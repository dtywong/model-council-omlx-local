# 本機 oMLX 議會

[English](omlx-local-council.md)

呢個分支喺原有嘅 `model-council` 參考項目上，加咗本機瀏覽器介面。

```text
一份簡報
   │
   ├── 三個本機席位並行獨立作答
   │
   ├── 使用者決定下一步
   │      └── 選做匿名互評，答案次序會打亂
   │
   └── 手動請主席整合，可以附上或略過互評
```

第一階段收集獨立答案。額外評審要時間同運算量，由使用者決定值唔值得做。最後主席主動篩選、衡量證據，亦可以剔除有問題嘅講法。各實作嘅詳細流程見[操作流程同流程圖](workflow_zhHK.md)。

## 分析同調整

呢個分支建基於 [kfc283-sudo/model-council](https://github.com/kfc283-sudo/model-council) 嘅 MIT 授權實作，沿用以下原則。

1. 同時將同一份簡報交畀每個席位。
2. 保持最初答案嘅獨立性，並展示分歧。
3. 有需要時，打亂答案次序同重新標籤，再畀評審指出優缺點、評分同排名。
4. 主席要明確揀證據，交代共識同分歧。
5. 由使用者決定額外互評嘅成本係咪值得付出。

oMLX 分支有以下實作。

- **連線方式。** 瀏覽器可以透過 `council/omlx_server.py` 本機代理，或者直接呼叫 oMLX 兼容 OpenAI 嘅 `/v1` API。
- **揀席位。** 從 `/v1/models` 讀取模型清單。用模型 ID 可以揀已安裝嘅 MLX 對話模型或視覺語言模型，包括 Qwen、LLaMA、Mistral、Gemma、DeepSeek、MiniMax、GLM 等。
- **顯示推理。** 將 `reasoning_content`、`reasoning` 或內嵌 `<think>...</think>` 內容放入可展開嘅推理區，答案文字會分開顯示。
- **視覺輸入。** 選填圖片會用 OpenAI 兼容嘅 `image_url` 資料部分傳送。瀏覽器會檢查三個席位嘅模型 ID 係咪似支援視覺輸入。oMLX 會按實際模型能力處理。
- **私隱。** 執行時嘅提示詞、答案、圖片同評語留喺記憶體。瀏覽器另外喺 localStorage 儲存草稿、模型選擇、設定同最近八份問題簡報。代理唔會寫議會逐字記錄。
- **介面偏好。** 頂欄 **ENG / 廣東話** 可以切換英文同香港廣東話，隔籬可揀跟隨系統、淺色或者深色。兩項偏好都會留喺瀏覽器。

互評資料唔包含答案標籤同模型 ID 嘅對照表。評審收到答案 A/B/C 等標籤，主席收到有標籤嘅答案同編號後嘅評語。答案文字本身仍然可能透露模型身份。

## 安裝指南

### 1. 所需環境

- 用 Apple Silicon 嘅 Mac，運行 macOS 15 或以上，以便運行 oMLX。
- Python 3.10 或以上。本機代理用 Python 標準程式庫，但執行 `python -m council.omlx_server` 時，`council` 套件初始化亦會載入 Bedrock 模組，所以目前需要安裝 `boto3`。只用本機代理毋須 AWS 憑證。
- 已安裝 oMLX，模型目錄至少有三個可用嘅對話模型。如要附圖，三個席位都要支援視覺輸入。
- 現代瀏覽器。

oMLX 文件見 [omlx.ai](https://omlx.ai/) 同[官方儲存庫](https://github.com/jundot/omlx)。快速開始用 `http://localhost:8000/v1` 嘅本機 OpenAI 兼容伺服器。

```bash
# 由 oMLX 管理嘅伺服器
omlx start

# 或者喺前景運行，指明模型目錄
omlx serve --model-dir ~/models
```

先開 oMLX，議會先可以搵到模型。

### 2. 啟動本項目

喺儲存庫根目錄執行。

```bash
python -m pip install boto3
python -m council.omlx_server
```

用瀏覽器打開 [http://127.0.0.1:8765](http://127.0.0.1:8765)。代理預設將請求送去 `http://127.0.0.1:8000`。要改 oMLX 網址或者介面連接埠，可以設定環境變數。

```bash
OMLX_BASE_URL=http://127.0.0.1:8000 COUNCIL_PORT=8765 python -m council.omlx_server
```

PowerShell 寫法如下。

```powershell
$env:OMLX_BASE_URL = "http://127.0.0.1:8000"
$env:COUNCIL_PORT = "8765"
python -m council.omlx_server
```

oMLX 需要驗證時，可設定 `OMLX_API_KEY`。喺代理模式，金鑰由 Python 代理使用。喺靜態網頁或直連模式，可以喺瀏覽器嘅 **oMLX** 設定輸入金鑰。金鑰會存入嗰個瀏覽器嘅 localStorage，以 Bearer 權杖形式傳畀已設定嘅 oMLX。

## GitHub Pages 同 Windows 存取

`web/` 可以當靜態網站部署，毋須額外前端套件。`.github/workflows/pages.yml` 會透過 GitHub Actions 發佈呢個資料夾。實際網址可以喺儲存庫 **Settings → Pages** 查到。

Windows 使用者可以直接打開已部署網頁，毋須 Python 或本機副本。撳頂欄嘅 **oMLX**，填寫以下資料。

1. **伺服器網址。** 填可以連到嘅 oMLX 根網址，例如 `https://mac.example.com:8000`。介面會為兼容 OpenAI 嘅 API 補上 `/v1`。
2. **API 金鑰。** 選填。填咗就會用 `Authorization: Bearer …` 傳送。

瀏覽器直連需要符合以下條件。

- oMLX 要監聽可以由客戶端連到嘅網絡介面。只監聽 Mac 本機嘅 `127.0.0.1` 唔夠。
- Windows 電腦要經同一個區域網絡、VPN 或安全通道連得到。
- HTTPS GitHub Pages 要連 HTTPS 端點。瀏覽器通常會封鎖混合內容入面嘅純 HTTP 端點。
- 透過 CORS 允許準確嘅 Pages 來源，例如 `https://dtywong.github.io`。

將 oMLX 放喺有保護嘅網絡，或者透過 VPN、有驗證嘅 HTTPS 反向代理或私人通道連線。用本機 Python 代理時，將設定入面嘅伺服器網址留空，再開 `http://127.0.0.1:8765`，金鑰可以留喺執行代理嘅主機上。

公開原始碼同 Pages 部署成品唔包含私人環境檔入面嘅伺服器地址同 API 金鑰。每位使用者透過介面自行設定。真實金鑰唔應該提交到儲存庫。就算輸入欄有遮罩，交畀瀏覽器嘅金鑰仍然可以被檢查。

## 使用指南

### 第一階段：獨立席位

1. 開 oMLX。如果之前已開介面，重新整理模型清單。
2. 揀三個唔同嘅模型。可以從清單揀，亦可以貼上自訂 oMLX 模型 ID。
3. 輸入一條問題或決策簡報。草稿會儲存喺瀏覽器。
4. 選擇用唔用**深度思考模式**，再設定思考 token 上限同答案 token 上限。
5. 可以附上一張圖片。使用圖片時，三個席位都要揀視覺語言模型。圖片上限係 8 MB。
6. 撳**問議會**，三席會並行收到同一份簡報。
7. 睇處理進度。瀏覽器直連會顯示有幾多席已回覆。經 Python 代理會顯示等候狀態，代理等所有席位完成後先會傳回結果。
8. 比較各席回覆。如果有提供，可以展開**深度思考過程**同**運行詳情**。

### 由使用者決定下一步

先讀各席獨立答案，再揀下面其中一步。

- 第一階段已經答得夠清楚，就停低。
- 問題影響大、答案有分歧或者想搵反例，可以做第二階段。
- 想直接由主席揀證據同整合，可以略過互評。

### 第二階段：選做匿名互評

1. 揀兩個唔同嘅評審模型。
2. 撳**開始匿名互評**。
3. 流程會移除答案附帶嘅模型身份資料，打亂答案次序，再加 A/B/C 標籤。
4. 兩個評審會各自檢視每份答案，指出優缺點、遺漏同錯誤，畀 1 至 10 分，再排次序。
5. 繼續之前，先睇匿名答案同兩份評語。

互評提供畀主席參考嘅證據，同時幫手搵遺漏同過分肯定嘅結論。

### 第三階段：主席整合

1. 揀主席模型。
2. 準備好就撳**請主席整合答案**。
3. 主席收到有標籤嘅答案。如果做過第二階段，亦會收到評語。主席要畀出清楚建議，交代共識、分歧同解決分歧嘅理由。
4. 用整合結果輔助決策。高影響嘅決定要獨立核實，最終決定由使用者負責。

### 本機儲存同私隱

localStorage 有目前草稿、模型 ID、思考設定、最多八份近期簡報、語言同外觀偏好。如果喺直連設定輸入咗 oMLX 網址同 API 金鑰，佢哋亦會留喺目前瀏覽器。模型答案、推理、互評資料同圖片唔會存入 localStorage，本機代理亦唔會儲存議會記錄。用**清除本機記錄**可以刪除近期問題。要移除 oMLX 網址同金鑰，就喺設定清空。

## 疑難排解

| 情況 | 點檢查 |
|---|---|
| oMLX 暫時用唔到 | 確認 oMLX 有運行，`OMLX_BASE_URL` 指向伺服器根網址，末尾唔使加 `/v1`。 |
| 搵唔到模型 | 確認 oMLX 設定嘅模型目錄有已安裝模型，再撳重新整理。 |
| 其中一席失敗 | 檢查模型 ID、可用統一記憶體同該席顯示嘅 oMLX 錯誤。 |
| 圖片請求失敗 | 三席都要用視覺語言模型，圖片要喺 8 MB 或以下。 |
| 冇顯示推理 | 模型可能冇傳回推理，或者深度思考已關閉。仍然可以用答案文字。 |
| 瀏覽器連唔到本機介面 | 開 `python -m council.omlx_server` 顯示嘅準確網址。預設連接埠係 8765。 |
| GitHub Pages 連唔到 | 檢查 oMLX 網址、HTTPS 或混合內容限制、CORS、防火牆或 VPN 同金鑰。 |
| 好似一直處理緊 | 瀏覽器等候模型回覆最多 180 秒，搵模型最多 15 秒。檢查 oMLX 記錄、模型載入、思考預算、模型能力同網絡。 |

## 呢個分支嘅主要檔案

- `council/omlx_server.py` 提供本機靜態網站、oMLX 代理、議會各階段，以及推理同圖片格式處理。
- `web/index.html`、`web/styles.css`、`web/app.js` 同 `web/preferences.js` 提供三席介面、瀏覽器筆記簿同介面偏好。
- `docs/omlx-local-council.md` 係英文分析同安裝使用指南。
