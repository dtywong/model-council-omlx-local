# 議會成員名冊範本

[English](member_registry.md)

名冊為每個可以做「席位」嘅模型留一條記錄，方便召集議會時查表，免得次次重新揀。以下係格式範例。

每項記錄應該包含以下資料。

- **點呼叫。** 保留可以執行嘅 API 呼叫、命令列指令或者 SDK 呼叫。
- **有冇參與互評。** 有啲模型只負責作答，例如未接駁結構化排名輸出，或者過往嘅排名幫助唔大。
- **預設負責咩任務。** 記低模型喺邊類任務有實績，亦要標明未測過嘅任務。要將某類任務嘅強項推廣到另一類，就先搵證據。
- **已知限制。** 例如速率限制、推理模型嘅最低 token 預算、編碼問題，或者實際呼叫遇過嘅情況。

## 記錄範例

### claude-tier-a：快而穩定嘅通用模型

- 呼叫方式：用代理框架嘅標準分派方法，揀中階模型。
- 參與互評：係。
- 預設任務：各類任務，適合作為日常作答席。

### claude-tier-b：同系列、更強而且運算量較大嘅模型

- 呼叫方式：用相同分派方法，揀最高階模型。
- 參與互評：係。
- 預設任務：判斷要求高或者影響大嘅問題。例行工作用較快嘅級別已經夠。

### open-model-a：另一個模型家族

- 呼叫方式：用服務商嘅 API 或命令列封裝。
- 參與互評：如果輸出可以配合其他評審用嘅排名格式，就可以互評。未支援之前只負責作答。
- 預設任務：各類任務，為議會引入訓練路線有差異嘅觀點。

### cloud-frontier-x / cloud-cheap-y：經共用雲端推理 API 呼叫嘅模型

- 通常有旗艦同低成本級別。旗艦可以放入高規格議會，低成本型適合預算有限嘅議會。將低成本模型同旗艦放喺同一組之前，睇吓[議會模式](pattern_zhHK.md)提到嘅組合觀察。
- 喺有版本記錄嘅地方寫低模型 ID，定期核對。供應商目錄會更新，目前可用嘅 ID 過幾個月可能已改。

### search-grounded-seat：靠即時網頁搜尋找證據嘅席位

- 參與互評：唔參與。呢一席負責研究。
- 預設任務：要查證最新事實或者搵引用資料嘅問題。純推理或者寫作任務可以略過。

## 預設席位組合

| 議會類型 | 建議席位 | 主席 |
|---|---|---|
| 高規格（影響最大嘅判斷） | 一個強通用模型，加兩個唔同訓練路線嘅旗艦席位 | 強通用模型 |
| 低成本（有預算限制但仍然需要判斷） | 三個低成本模型，來自至少兩條唔同訓練路線 | 最快而有能力嘅模型 |
| 原文列作反例 | 純粹為咗增加意見，用一個強模型加一至兩個中階模型 | —（一次實測入面，呢個組合分數低過單用強模型） |

以上係起點。之後可以按[評分表](scorecard_schema_zhHK.md)累積嘅證據調整。
