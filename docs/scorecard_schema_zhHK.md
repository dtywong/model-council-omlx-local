# 議會評分表格式

[English](scorecard_schema.md)

要判斷邊個模型擅長邊類問題，靠嘅係逐次累積嘅實績。呢份文件定義欄位。真實記錄請放喺自己保管嘅副本。

## 欄位

| 欄位 | 意思 |
|---|---|
| 日期 | 議會幾時執行 |
| 任務類型 | 問題類別，例如寫作、程式碼、財務判斷或者研究方法評議 |
| 成員 | 呢一行屬於邊個席位 |
| 平均互評排名 | 其他評審喺匿名情況下畀嘅平均排名。1 代表最好。冇做互評就留空。 |
| 獨有貢獻 | 用一句短語記低呢一席搵到或者補充咗咩 |
| 人手判斷 | 負責主持嘅人回頭睇，覺得呢一席嘅貢獻係咪站得住腳 |

## 點解用呢個格式

- **記其他評審嘅排名。** 由睇唔到作者身份嘅其他評審評價，重點係知道答案喺其他席位眼中有幾可靠。
- **每行只寫一個重點。** 方便快速比較幾十次執行。要保留逐份答案，可以喺每次執行嘅記錄另外保存。
- **由人作判斷。** 表格記錄發生過嘅事。保留邊啲席位，由為相關決策負責嘅人決定。

## 點樣長期運用

- **淘汰表現欠佳嘅席位。** 如果某模型連續幾次排最尾，或者冇帶來獨有觀點，就考慮移除。
- **提拔有貢獻嘅席位。** 如果某模型多次搵到其他席位忽略嘅問題，可以由額外選項變成預設。
- **模型更新後再測。** 升版可能令表現變好或者變差。將新版本當成新候選模型測試。
- **按項目保管，或者集中管理。** 共用表可以睇到最全面嘅表現。分項目記錄就較容易保護敏感資料。
